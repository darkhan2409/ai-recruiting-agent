# Политика работы с данными — HCB Recruiting Agent

> Система обрабатывает персональные данные кандидатов. Banking compliance — обязателен.

---

## Какие PII в системе

В резюме кандидатов: ФИО, email, телефон, опыт работы, образование, навыки, иногда фото и дата рождения. Файлы PDF/DOCX с оригиналами.

**Под действие закона РК "О персональных данных и их защите" (152-V) попадает всё перечисленное.**

## Где хранятся данные

| Хранилище | Что | Доступ |
|---|---|---|
| PostgreSQL `candidates.parsed_data` | Структурированные PII (JSONB) | Только сервисный аккаунт API |
| PostgreSQL `matches` | Связки кандидат↔вакансия + объяснения | Только API |
| Qdrant | Эмбеддинги резюме (numerical, не PII) | Только API |
| Filesystem `/storage/resumes/` | Оригинальные файлы | Только API + рекрутер через UI |

`.env` с кредами — никогда в git. `.gitignore` обязателен.

## Логи

**Никогда не логировать в plain text:**
- Полные тексты резюме
- ФИО кандидатов
- Email и телефоны
- Содержимое `.env`

**Маскировка перед логированием:**
- Email: `ivan.petrov@gmail.com` → `i***@gmail.com`
- Телефон: `+77071234567` → `+7707***4567`
- ФИО: использовать только `candidate_id` (UUID), не имя
- Резюме целиком: только `candidate_id` + длина символов

В коде — функция `mask_pii(text)` в `src/utils/pii.py`, применяется до `logger.info()`.

## Внешние сервисы — главный data flow

**Резюме целиком отправляются в OpenAI** для:
1. LLM extraction (gpt-4o-mini) — парсинг текста в `Resume` схему
2. LLM judge (gpt-4o) — оценка соответствия вакансии

**Это критичный data flow.** Каждое резюме покидает периметр банка.

### Митигация для production

1. **OpenAI Enterprise + Zero Data Retention** — платный tier, OpenAI не хранит запросы и не использует для обучения. Документировать и закупать перед прод-запуском
2. **Альтернатива для high-sensitivity:** локальная LLM на инфре банка (Qwen2.5-72B, Llama-3.1-70B через vLLM)
3. **Договор с кандидатом:** при отправке на `cv@...` — auto-reply с согласием на обработку ПД и передачу третьим лицам (OpenAI)

### В MVP / для демо

Все резюме в `tests/fixtures/` — **синтетические, сгенерированы LLM**. Реальных PII нет. На защите явно проговорить: "тестовые данные синтетические, для прода — OpenAI ZDR или локальная модель".

## Retention и право на удаление

- Резюме хранятся **не дольше 6 месяцев** с момента поступления (configurable через `RESUME_RETENTION_DAYS`)
- По истечении — фоновая задача удаляет файл + parsed_data + эмбеддинг + матчи
- **Right to be forgotten:** `DELETE /candidates/{id}` каскадно удаляет всё (DB + Qdrant + file)
- Удаление логируется в audit trail

## Quarantine

Сомнительные резюме (битый файл, не похоже на резюме, prompt injection попытка) могут содержать частичные PII → **тот же режим хранения и удаления**, что и обычных кандидатов.

## Доступ к системе

- В MVP аутентификации нет — это known limitation, явно указать в README
- В production: OAuth2 / SSO через корпоративный Active Directory банка
- Audit log: кто и какие резюме просматривал, когда
